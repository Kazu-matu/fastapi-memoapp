## 2. テスト方針

```text
1. テスト用 DB はインメモリ SQLite を使用する（本番 DB には絶対に接続しない）
2. テスト関数ごとに DB をリセットする（setup_db フィクスチャ）
3. テストは独立して実行できる状態を維持する（テスト間でデータを引き継がない）
4. 単体テスト → 結合テスト → E2E の順で実施する
5. 全テストが PASSED であることをリリース条件とする
```

---

## 3. テスト構成

```text
tests/

```

## 6. E2E テスト仕様（Playwright）

ファイル: `tests/e2e/test_app.py`

**前提:** `uv run uvicorn main:app --reload` でサーバーを起動した状態で実行する。

| テスト ID | テスト内容 | 操作手順 | 期待結果 |
| --- | --- | --- | --- |
| E2E-01 | データ新規登録 | フォームに入力 → 「登録」ボタン押下 | 「登録しました」メッセージ表示・一覧に追加 |
| E2E-02 | 一覧表示 | トップページを開く | 登録済みデータが一覧テーブルに表示 |
| E2E-03 | データ編集 | 「編集」ボタン → フォーム変更 → 「更新」 | 「更新しました」メッセージ表示・一覧が更新 |
| E2E-04 | データ削除 | 「削除」ボタン → 確認ダイアログで OK | 「削除しました」メッセージ・一覧から消える |
| E2E-05 | 必須入力チェック | タイトル空のまま「登録」 | HTML バリデーションによりフォームが送信されない |
| E2E-06 | 削除キャンセル | 「削除」ボタン → 確認ダイアログでキャンセル | 削除されない・一覧に残る |

## 7. テスト実行手順

```bash
# 1. 依存パッケージのインストール
uv sync

# 2. 単体テスト + 結合テストを実行
uv run pytest tests/unit/ tests/integration/ -v

# 3. 結果をファイルに保存（報告書に添付する）
uv run pytest tests/unit/ tests/integration/ -v > docs/test_result.txt 2>&1

# 4. E2E テスト（サーバー起動後に別ターミナルで実行）
uv run uvicorn main:app --reload
uv run pytest tests/e2e/ -v

# 5. Playwright のブラウザインストール（初回のみ）
uv run playwright install chromium
```
