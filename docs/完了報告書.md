## 3. KPT 振り返り

### ✅ Keep（うまくいったこと・続けること）

**開発プロセス**

- 実装の順番（models → schemas → cruds → routers → templates → tests）を守ったことで、手戻りが少なかった
- `flush()` → `commit()` のトランザクション設計を全 CRUD に統一できた。一貫性が高くバグが起きにくい構造になった
- `.env` + `python-dotenv` による設定管理を最初から導入したことで、DB 切り替えが 1 行の変更で済む構成になった
- テストで `async_sessionmaker` + インメモリ SQLite を使い、本番 DB に触れずに結合テストが実行できた

**ドキュメント**

- コードと同時進行でドキュメントを作成したことで、実装の意図が鮮明に記録できた
- CLAUDE.md（AI 指示書）を作成したことで、次回以降は「このファイルを守って」という一言で開発スタートできる体制が整った
- 全ドキュメントへのメタヘッダー（作成日・最終更新日・版数）を規約化したことで、ドキュメントの鮮度管理がしやすくなった

---

### ⚠️ Problem（問題・課題）

**テスト**

- E2E テスト（Playwright）はサーバーを手動で起動してから実行する必要があり、CI に組み込めていない
- `tests/e2e/test_memo_app.py` は旧 SPA 構成（`frontapp/`）向けのままで、Jinja2 構成への更新が未完了

**コード**

- `main（リファクタリング前）.py` というバックアップファイルがリポジトリに含まれてしまった。不要ファイルの除外が不十分だった
- `frontapp/` ディレクトリ（旧 SPA 版）がリポジトリに残っており、新規利用者が混乱する可能性がある

**ドキュメント**

- 仕様書の処理フロー図がテキストベースで視認性が低い。図（draw.io 等）での表現が望ましい
- README の本番環境構築手順（PostgreSQL のインストール・ユーザー作成）が省略されている

---

### 🔄 Try（次回試すこと・改善策）

**テスト・CI**

- GitHub Actions で `uv run pytest tests/unit/ tests/integration/ -v` を自動実行する CI を追加する
- E2E テストを Jinja2 構成（`http://localhost:8000/`）向けに書き直し、`uvicorn` 起動を pytest フィクスチャで自動化する

**コード品質**

- `frontapp/` と `main（リファクタリング前）.py` を削除し、リポジトリをクリーンにする
- `ruff` / `mypy` を開発依存に追加し、静的解析をローカルおよび CI で実行できるようにする

**ドキュメント**

- 仕様書の ER 図を Mermaid 記法で書き直し、GitHub 上でそのまま図として表示されるようにする
- README に PostgreSQL の環境構築手順（Docker Compose）を追記する
- GUIDE.md に「Docker で環境を作る方法」のセクションを追加し、環境構築の手間をさらに減らす

**学習コンテンツ**

- 「事例で学ぶ Web 開発入門」に認証（ログイン機能）の章を追加する（次のステップとして需要が高い）
- 演習問題（「支出管理アプリを作ってみよう」など）を GUIDE.md に追加する
