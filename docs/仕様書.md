# メモアプリ 仕様書

## 1. システム概要

FastAPI + Jinja2 によるサーバーサイドレンダリング構成のメモ管理 Web アプリケーション。
PRG（Post-Redirect-Get）パターンを採用し、フォーム送信後のリロード二重登録を防止する。
変更履歴の自動記録・論理削除・監査フィールド（登録者/更新者）に対応する。

| パッケージ管理 | uv（`pyproject.toml`） |

## 5. スキーマ定義（Pydantic）

`schemas/memo.py` で定義。リクエスト・レスポンスのバリデーションに使用。

```
MemoStatusSchema
  ├── priority: str         # 優先度（"高"/"中"/"低"）
  ├── due_date: datetime | None
  └── is_completed: bool    # default: False

InsertAndUpdateMemoSchema
  ├── title: str            # 必須、1文字以上
  ├── description: str      # 任意
  └── status: MemoStatusSchema

MemoSchema                  # レスポンス用（InsertAndUpdateMemoSchema を継承）
  ├── memo_id: int
  ├── created_at: datetime
  ├── updated_at: datetime | None
  ├── created_by: str
  ├── updated_by: str | None
  └── is_deleted: bool

MemoHistorySchema           # 履歴レスポンス用
  ├── history_id: int
  ├── memo_id: int
  ├── action: str
  ├── changed_at: datetime
  ├── changed_by: str
  ├── title: str
  ├── priority: str
  ├── due_date: datetime | None
  └── is_completed: bool

ResponseSchema
  └── message: str
```

## 6. API エンドポイント一覧

ベース URL: `http://localhost:8000/api/memos`

| メソッド | パス | 処理 | ステータス | リクエスト | レスポンス |
| --- | --- | --- | --- | --- | --- |
| POST | `/` | メモ新規登録 | 201 | `InsertAndUpdateMemoSchema` | `ResponseSchema` |
| GET | `/` | メモ全件取得 | 200 | なし | `list[MemoSchema]` |
| GET | `/{memo_id}` | メモ1件取得 | 200 | なし | `MemoSchema` |
| PUT | `/{memo_id}` | メモ更新 | 200 | `InsertAndUpdateMemoSchema` | `ResponseSchema` |
| DELETE | `/{memo_id}` | 論理削除 | 200 | なし | `ResponseSchema` |
| GET | `/{memo_id}/histories` | 変更履歴取得 | 200 | なし | `list[MemoHistorySchema]` |

### ページルーター（Jinja2）

| メソッド | パス | 処理 |
| --- | --- | --- |
| GET | `/` | 一覧・作成フォーム表示 |
| POST | `/memos` | メモ登録 → リダイレクト（PRG） |
| GET | `/memos/{id}/edit` | 編集フォーム表示 |
| POST | `/memos/{id}/edit` | メモ更新 → リダイレクト（PRG） |
| POST | `/memos/{id}/delete` | メモ削除 → リダイレクト（PRG） |

### エラーレスポンス

| ステータスコード | 発生条件 |
| --- | --- |
| 404 | 指定した `memo_id` が存在しない、または論理削除済み |
| 422 | リクエストボディのバリデーションエラー |

## 7. 処理フロー

### 7-1. メモ新規登録（POST /memos → リダイレクト）

```
[ブラウザ（フォーム送信）]
  ↓ POST /memos（multipart/form-data）
[routers/pages.py: create_memo()]
  ↓ InsertAndUpdateMemoSchema でバリデーション
  ↓ memo_crud.insert_memo(session, memo_data, login_user)
[cruds/memo.py: insert_memo()]
  ↓ Memo インスタンス生成（created_by / updated_by = login_user）
  ↓ db.add(memo) → db.flush()  ← memo_id を確定（未コミット）
  ↓ MemoHistory(action="CREATE") を生成・追加
  ↓ db.commit()  ← memos + memo_histories を1トランザクションで確定
  ↑ 例外時: db.rollback()
[routers/pages.py]
  ↑ RedirectResponse("/?msg=created", 303)  ← PRG パターン
[ブラウザ]
  ↑ GET / でフラッシュメッセージを表示
```

### 7-2. 論理削除（POST /memos/{id}/delete → リダイレクト）

```
[cruds/memo.py: delete_memo()]
  ↓ is_deleted = True
  ↓ deleted_at = datetime.now()
  ↓ MemoHistory(action="DELETE") を追加
  ↓ db.commit()
  ↑ 以降の get_memos / get_memo_by_id は is_deleted == False でフィルタ
```

### 7-3. DB 切り替え（SQLite ↔ PostgreSQL）

```
[config.py]
  ↓ .env から DATABASE_URL を読み込む

[db.py: _build_engine()]
  ↓ URL が "sqlite" で始まる
  │   → NullPool + check_same_thread=False
  ↓ URL が "postgresql" で始まる
      → QueuePool + pool_pre_ping + pool_size=5 / max_overflow=10
```

## 8. DB 初期化手順

```bash
# テーブルを DROP → CREATE（既存データは全削除）
uv run python init_database.py
```

---

## 9. アプリ起動手順

```bash
# 依存パッケージのインストール
uv sync               # 開発（SQLite）
uv sync --extra prod  # 本番（PostgreSQL 追加）

# .env を設定
cp .env.example .env
# DATABASE_URL を環境に合わせて編集

# テーブル初期化
uv run python init_database.py

# サーバー起動
uv run uvicorn main:app --reload
```
